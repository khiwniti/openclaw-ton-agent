## 3. CURRENT BLOCKER

### Scanner Runtime Crash (PERSISTS)
**Symptom:** All scanner machines crash on startup with:
```
TypeError: (0 , import_shared.createLogger) is not a function
    at /app/packages/scanner/src/index.ts:20:13
```

**Root cause hypothesis:**
- The deployed image still contains the old `packages/shared` code despite local source fixes and no-cache rebuilds.
- The scanner process runs `npm --workspace packages/scanner run start`, which executes `tsx src/index.ts`.
- `tsx` compiles TypeScript at runtime from `/app/packages/scanner/src/index.ts`, which imports from `@openclaw-ton-agent/shared`.
- The `@openclaw-ton-agent/shared` package in `/app/packages/shared/src/index.ts` is **supposed** to export `createLogger`, but the runtime error indicates it does not in the deployed image.

**Key evidence:**
1. Local source files have the correct exports (verified via `cat`).
2. Multiple redeployments with `--no-cache` and `CACHEBUST` did not fix the issue.
3. Machine logs consistently show old behavior, suggesting either:
   - The build is not picking up the source changes
   - There is a cached layer or symlink/hardlink issue
   - The `COPY --from=builder` in Dockerfile is not actually copying updated files

**Next session must:**
1. Inspect the actual file contents inside a running or stopped machine via `flyctl ssh console` or by adding a debug command.
2. Verify whether `packages/shared/src/index.ts` and `packages/shared/src/schemas.ts` in the image contain `createLogger`.
3. If the files are stale, investigate Docker layer caching or build context issues.
4. If the files are current, investigate whether `@openclaw-ton-agent/shared` resolves to a different path in the runtime image.
